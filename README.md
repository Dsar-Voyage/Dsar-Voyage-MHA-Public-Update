# My Hero Academia: Your Story — Public Update Repository

The world JSON of the Voyage world **My Hero Academia: Your Story** by Dsar, split into sections so anyone
can bring their own save or remix up to date with an update.

The world already has remixing on, so its full build is public anyway. This repository makes it easy to
use: every section and every big entry (each trigger, NPC, event, trait, quest ...) has its own file, and
every published update lists exactly which sections and entries changed.

## What's here

| Path | What it is |
|---|---|
| [`CHANGES.md`](CHANGES.md) | **Start here.** One entry per published update: what changed, why, and which files to copy. |
| [`SECTIONS.md`](SECTIONS.md) | Every section with its category, size, entry count and whether it changed in the latest update. |
| [`sections/`](sections/) | One file per section: the exact value of that section. |
| [`entries/`](entries/) | The big sections split into one file per entry, each folder with an `INDEX.md` (entry name → file). |
| [`world/MHA_Your_Story.json`](world/MHA_Your_Story.json) | The complete world document (`data.world`), as published. |
| [`world/MHA_Your_Story.studio.json`](world/MHA_Your_Story.studio.json) | `initialGameState` only, the editor's world JSON. |
| [`releases/`](releases/) | Per release: `<release>.changes.md` (machine list of changed sections and entries) and `<release>.hashes.json`. |
| [`MANIFEST.json`](MANIFEST.json) | Current release, schema version and file hashes. |

The files use Voyage's current (2.52) layout: triggers are in `triggerDefinitions`, and quests, quest
triggers, arcs and narrative events are inside `parties` (the files `parties.quests`,
`parties.questTriggers`, `parties.arcs`, `parties.narrativeEvents`).

## Updating your own save or remix

**The easiest way to get an update is to start a new game.** Use this repository when you want to keep a
save going, or when you've customized your own remix and only want the parts that changed.

1. **Back up first.** Copy your save's or remix's world JSON somewhere safe before you change anything.
2. Open [`CHANGES.md`](CHANGES.md) and find every update newer than the one your save started on.
3. For each changed section, copy from this repository into the same place in your save or remix:
   - a section marked **whole section** → copy `sections/<section>.json` over that section;
   - a section with **Added / Modified** entries → open `entries/<section>/INDEX.md`, find the entry, and copy its file's value into the entry with the same key (or add it, if it's new);
   - **Removed** entries → delete that key from your save.
4. Only copy **content** and **settings** sections (see [`SECTIONS.md`](SECTIONS.md)). Leave **meta**
   sections such as `compatibilityRevision` and `heroesVersion` alone.
5. Updates that change many triggers work best on a new game: triggers keep their own state, and a running
   save may already be past the moment a new trigger looks for.

Where to edit:
- **A remix:** open it in Voyage Studio and paste into the matching section of the world JSON.
- **A running game:** Settings → Creator Tools → **State Editor** (search for the entry's name; triggers
  appear under *Parties → Triggers*).

## Rules for this repository

- It holds **published releases only**. A draft never appears here before it's published.
- Every published update gets a [`CHANGES.md`](CHANGES.md) entry naming the changed sections and entries.
- Files are generated by [`tools/build_release.py`](tools/build_release.py) from the published world
  document; nothing is edited by hand.
- Images, music and voices are hosted by Voyage and are not copied here; the files point to them.

## Release process (maintainers)

```sh
python tools/build_release.py --label <release> --source <published world.json> \
    --previous releases/<previous release>.hashes.json --published <YYYY-MM-DD>
```

Then add the release's entry at the top of `CHANGES.md` (copy the section list from
`releases/<release>.changes.md` and add the why), and commit everything in one commit.
